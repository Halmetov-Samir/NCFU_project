 MD5 Distributed Bruteforce

Распределённая система подбора PIN-кода по его MD5-хэшу.
Сервер-координатор + N воркеров, работающих параллельно, в том числе с разных машин через интернет.




Проект решает одну задачу: найти PIN-код, зная только его MD5-хэш. PIN короткий (4, 6 или 8 цифр).Чтобы ускорить процесс, работа распределяется между воркерами — они могут быть на одной машине или на разных, соединённых через интернет.

Сервер-координатор сам не перебирает — он только выдаёт задания, принимает результаты и следит за состоянием системы. Воркеры получают диапазоны чисел, перебирают их, считают MD5 и сравнивают с целевым хэшем. Как только один воркер находит совпадение, сервер рассылает всем сигнал остановки.

Нагрузка перераспределяется динамически: быстрый воркер, закончив свой диапазон, сразу берёт новый чанк и не простаивает. Если сервер не получает от воркера heartbeat дольше таймаута — воркер считается мёртвым, а его диапазон возвращается в общий пул. На стороне воркера есть Circuit Breaker: при недоступности сервера он не зависает, а ждёт и пробует переподключиться.

Наблюдать за процессом можно через веб-интерфейс: он обновляется в реальном времени через SSE (без F5) и показывает прогресс, скорость (PIN/сек), активных воркеров и историю попыток.


Архитектура

Система состоит из трёх частей: сервер-координатор, воркеры и веб-интерфейс.

Сервер хранит целевой хэш и длину PIN, разбивает пространство значений на чанки и выдаёт их воркерам. Он не считает MD5 — только управляет работой: принимает heartbeat'ы, фиксирует результат, рассылает STOP-сигнал, ведёт историю. Общение идёт через REST API, поэтому воркер можно поднять на любой платформе с HTTP-клиентом.

Воркер — вычислительный процесс. При старте регистрируется, получает первый диапазон и начинает перебор. Внутри работает несколько потоков: Producer генерирует числа и кладёт в очередь, Consumers забирают их, считают MD5 и сравнивают с целью. Когда диапазон заканчивается — воркер просит у сервера следующий.

Веб-интерфейс — HTML-страница с JavaScript. Через REST задаёт хэш и длину PIN, запускает и останавливает перебор, а через SSE получает мгновенные обновления прогресса.



 Паттерны проектирования

Producer-Consumer — внутри воркера. Один поток генерирует числа и складывает в очередь, несколько потоков забирают и обрабатывают. Так вычисления распараллеливаются без ручной синхронизации.

Work Stealing — воркер, закончив диапазон, не завершается, а берёт у сервера следующий чанк. Быстрые воркеры делают больше работы, медленные — меньше, общее время сокращается.

Heartbeat — воркер периодически сообщает серверу «я жив». Если сигнал пропал — сервер считает воркер мёртвым и возвращает его диапазон в пул.

Circuit Breaker— при недоступности сервера воркер не долбит его бесконечно и не падает, а переходит в режим ожидания и периодически пробует восстановить связь.

Rate Limiting — ограничение запросов с одного IP (200/сек) защищает сервер от перегрузки.

SSE — сервер держит открытое соединение и шлёт события в браузер: прогресс, скорость, регистрация воркеров, нахождение PIN. Страница обновляется без перезагрузки.


API
Управление задачей:`POST /api/start` задаёт хэш и длину PIN, `POST /api/stop` останавливает перебор, `GET /api/status` возвращает прогресс, скорость, воркеров и историю.

Сервер — HTTP-роуты, менеджер задач, хранилище состояния, rate limiter, SSE-канал. Воркер — HTTP-клиент, Producer-Consumer-пул потоков, MD5-обработчик, Circuit Breaker. Веб-интерфейс— статические HTML/CSS/JS, подписка на SSE и визуализация прогресса.
